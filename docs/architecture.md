# Cumulus System Architecture Specification

## Architecture Overview

**Cumulus** is designed as a standalone, zero-framework Neovim distribution. It operates directly on native `lazy.nvim` plugin specifications to manage a modular `cumulus.*` namespace.

---

## Directory Hierarchy & Namespace Layout

```
init.lua                        # Bootstraps lazy.nvim and loads cumulus.plugins
lua/
└── cumulus/
    ├── init.lua                # Entry setup module
    ├── core/
    │   ├── options.lua         # Vim options (timeouts, relative numbers, leader)
    │   ├── keymaps.lua         # Global navigation & split keymaps
    │   └── autocmds.lua        # Auto-save, filetype triggers, IaC helpers
    ├── theme/
    │   ├── init.lua            # Theme engine bootstrapper (colorscheme aws-theme)
    │   └── aws.lua             # AWS Palette definition & highlight group mapping
    ├── plugins/
    │   ├── core-treesitter.lua # Treesitter parsers (HCL, YAML, Dockerfile, Bash)
    │   ├── core-mason.lua      # Mason tool pinning & installer spec
    │   ├── core-lsp.lua        # nvim-lspconfig setups (terraformls, yamlls, ansiblels, etc.)
    │   ├── cloud-terraform.lua # Terraform & OpenTofu integration
    │   ├── cloud-aws.lua       # CloudFormation & SAM integration
    │   ├── cloud-ansible.lua   # Ansible playbook integration
    │   ├── cloud-k8s.lua       # Helm & Docker specs
    │   ├── tools-formatting.lua# conform.nvim setup
    │   ├── tools-linting.lua   # nvim-lint setup
    │   └── ui-*.lua            # Dashboard, lualine, bufferline, noice specs
    └── util/
        ├── iac.lua             # Split terminal IaC runners
        ├── maven.lua           # Maven goals & wrapper runner
        └── gradle.lua          # Gradle tasks & wrapper runner
```

## AWS Theme Visual Token Architecture

The AWS Theme is loaded programmatically via `lua/cumulus/theme/aws.lua`.

* **Primary Accent (AWS Orange):** `#FF9900`
* **Secondary Accent (Dim Orange):** `#CC7A00`
* **Deep Dark Navy Background:** `#071521`
* **Sidebar Background:** `#040D17`
* **Statusline Background:** `#020A12`

### Floating Window Invariants
To prevent floating window border artifacts, `FloatBorder` is explicitly configured with `aws_orange` (`#FF9900`) foreground and `"NONE"` background, matching `NormalFloat`.

## Bootstrapping & Lifecycle Control

1. `init.lua` loads `cumulus.core.options` to set options and leader key (`<Space>`).
2. `init.lua` checks for `lazy.nvim` on disk; if absent, clones it.
3. `lazy.nvim` initializes plugin specs from `cumulus.plugins`.
4. Theme engine sets `aws-theme` as default.
5. Neovim triggers `VeryLazy`, loading `cumulus.core.keymaps` and `cumulus.core.autocmds`.

## Ecosystem Terminology & Module Roles

To prevent confusion between similarly-named tools in the Neovim ecosystem:

| Module / Component | Type | Responsibility |
| :--- | :--- | :--- |
| **`lazy.nvim`** | Plugin Manager | Bootstrapped in `lua/cumulus/core/lazy.lua` to load plugin specifications under `cumulus.plugins`. |
| **`lazy-lock.json`** | Lockfile | Auto-generated by `lazy.nvim` to pin exact Git commit SHAs across 40+ plugins for reproducible environments. |
| **`lazygit`** | Terminal TUI | External Git interface launched in a popup terminal via `<leader>og` (DevTools). |
